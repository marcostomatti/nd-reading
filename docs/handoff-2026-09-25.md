# Handoff, 2026-09-25

This repository came out of a workshop session in the coco repository (Open Tomato's
writing desk), on how agents write for Marcos, a neurodivergent reader: ADHD, a
developmental language disorder, and English as a second language. The workshop's source
material stays in coco, at
`~/projects/open-tomato/coco/docs/specs/nd-reading-and-no-blame/`: his own words to the
desk, paco's proposal for turning article rules into chat rules, and the first draft of
the no-blame rule. Everything the workshop produced moved here.

## Decisions already made

| Decision | Detail |
|---|---|
| Structure | One skill folder: a core that stays on, plus one module per scenario, read when its trigger fires. Triggers may overlap; a saved preference or one format question settles the overlap. |
| One ending | Core rule 3. A reply ends on one question or one next action. Several calls to action at the end count as a failure, and the text says why. |
| Diagrams | Plain-text outlines. Marcos's viewer shows Mermaid as code text. |
| Analogies | Agents may offer their own, one per idea, and say where it stops fitting. The reader's analogies are always kept and answered inside first. |
| Term density | "One new term per sentence" stays a number, so evals can check it. |
| Format question | Asked once per kind of content per session. Saved only after a yes. |
| Home and name | This repository, separate from coco, with no personal names in the skill or the rule. `nd-reading` is a working name. |
| Paco | Not needed here. The skill uses paco's rules and does not call the agent. |

Marcos's topics B and C are written into the text and have not been reviewed by him yet.
B, the reading of a sharp change of subject, is in the core and routes to `ideation.md`
or `debugging.md`. C, the reframing of how this reader ideates, opens the core and fills
`ideation.md`.

## What the first test found

Six cases ran once each with no skill, with the current skill, and with the single-file
draft, and a judge scored them without knowing which was which. The draft scored 5.0 on
followability against 3.3 for the current skill, met 21 of 21 case criteria against 15,
and had no blame wording. It was a little longer and a little slower to reach the action.
Hanging threads and stripped analogies did not show up with the current skill, so their
rules are untested. The full numbers and limits are in
`evals/results/smoke-2026-09-25.md`.

## What a new session here would not know

- **Memory does not carry over.** Claude Code keeps auto-memory per git repository, so
  the coco memories about how Marcos reads do not load here. Their content is in the
  skill. The originals are in
  `~/.claude/projects/-Users-marcos-projects-open-tomato-coco/memory/`:
  `plain-connected-sentences`, `marcos-writing-traits`, `one-ending-no-footers` and
  `divergent-ideation-support`.
- **The harness runs with tools off.** It pastes one skill file into the prompt, which
  is why the bundle script exists, and its example runner pins a model in
  `evals/runners.example.json` of the upstream repository.
- **Subagent tests share the session's context.** Test agents started from Claude Code
  load the user's global rules and this repository's files. All conditions share that
  context, so comparisons hold, while absolute scores may read better than a clean run.
- **The upstream clone** is at `~/projects/claude-code-stuff/i-have-adhd`, with the
  harness in `scripts/run_evals.py`. The current `marcos-has-adhd` skill has the same text
  as its `skills/i-have-adhd/SKILL.md`.
