# Smoke test, 2026-09-25

A first reading of the draft skill against the current one. It has one reply per case and
condition, and one judge, so it can show a direction and cannot settle anything. The
upstream harness, with three trials per case and the 14 upstream cases added, is the test
that would.

## How it ran

Six of the cases in `../cases.jsonl` were run under three conditions. The file had ten
cases at the time; the two hanging-thread and analogy cases added after this run were
not run.

| Condition | What the replying agent had |
|---|---|
| `baseline` | No skill |
| `comparator` | The current `marcos-has-adhd` skill, which has the same text as `i-have-adhd` |
| `candidate` | The single-file draft. `tested-skill-2026-09-25.md` holds its final text, which adds the two changes listed below and a later edit to the pre-send check |

Each reply came from a fresh Claude Code subagent (claude-opus-5-5, Claude Code 2.1.281)
that read the skill file, when there was one, and wrote a single reply. The subagents ran
inside the coco repository, so they loaded its AGENTS.md and the user's global rules. All
three conditions shared that context, which may make the no-skill replies look better than
a clean baseline would.

A separate judge agent scored the 18 replies with the condition names hidden and the labels
shuffled per case. It used the upstream rubric plus `../rubric-addendum.md`. The replies
are in `smoke-2026-09-25.responses.jsonl`, the scores in `smoke-2026-09-25.scores.jsonl`,
and the label key in `smoke-2026-09-25.blind-key.json`.

## What each failure looked like

**The compressed towel.** The current skill produced fewer dense sentences than no skill
(1.17 against 2.33 per reply), and its followability was about the same (3.33 against
3.50). So in these six cases the towel shows up with or without the skill, and the
current skill does not make it worse on average. The draft brought dense sentences down to
0.33 per reply. The clearest single case is the Vercel 504 question: four dense sentences
with the current skill, one with the draft.

**Cause chains cut into lists.** The current skill turned the cause of the timezone bug
into a numbered list of four items, and it did the same in the second-pass case with five
items. That matches the README's reading of rule 2: "more than one step" is met by any
explanation with parts. The draft told both causes in connected sentences and used
numbered lists only for actions.

**Hanging threads.** This did not appear. In the Docker case all three replies came back
to the base image, which was the open thread. The earlier turn in that case says "which
I'll look at next", and that probably makes the thread too easy to see. A harder case
needs a follow-up that pulls further away from the open question.

**Analogies stripped.** This did not appear either. All three replies kept the kitchen
image, and the current skill used it well in a mapping table. Pre-send check 5 seems to
reach the agent's own figures of speech more than the reader's. The draft was the only
reply that said where the kitchen picture stops fitting.

**Blame.** The no-skill reply to the migration case said "That's my miss", and the
no-skill second-pass reply opened with "Sorry, that was too compressed". The current
skill avoided both and still opened with "my migration". The draft replies had none of
these shapes.

## Costs of the draft

The draft replies were a little less concise than the current skill's (3.67 against 4.00)
and a little slower to reach the action (4.50 against 5.00). The longest draft reply, the
kitchen case, ran to 790 words, where the current skill used 465. Unpacking every term
makes a reply longer when the reply uses many terms.

The draft also lost a correctness point in the migration case. Its reply opened with a
MySQL-shaped explanation before it said the database type was unknown, and its line about
older SQLite versions was inaccurate.

## Changes made after this run

Two lines went into the draft in response:

- Rule 8: "When more than one mechanism fits the facts, lead with what is known, then name
  the check that tells them apart."
- Rule 11: "Use only the terms this step needs. Each new term costs a clause to unpack, so
  a term left out is cheaper than a term explained. Offer the rest as a next question."

The two affected cases were run once more with the updated draft. See the next section.

## Re-run after the changes

The two replies are in `smoke-2026-09-25.v2-responses.jsonl`. They were read directly and
not blind-judged, so treat this section as a check of the two changes and nothing more.

**Migration case.** The reply opens with what is known: the view's query still asks for
`email`, and the migration changed the table without changing the view. It then says what
is not known yet, which is why the view kept the old name. It says, correctly, that
Postgres normally updates a plain view on a rename, and it names the two causes that fit,
with one query that tells them apart. The MySQL and SQLite lines are gone. It has no blame
wording, and it runs to 336 words.

**Kitchen case.** The reply is down from 790 to 606 words; the current skill's reply was
465. It still names the concept, keeps the kitchen table, and says where the picture stops
fitting. Two topics that the first draft reply explained in full, the duplicate email and
the crash between saving and publishing, are now offered as a next question. It still
unpacks each new term (broker, acknowledgement, publishing, durable) where it first
appears, and its only numbered list is the five setup steps.

## What this run cannot tell

- One reply per cell. A second or third trial could reverse any single-case difference.
- One judge, from the same model family as the replying agents.
- Hanging threads and stripped analogies did not appear with the current skill, so the
  draft's rules 13 and 14 are untested here. They need harder cases.
- The upstream 14 cases were not run, so a regression in the six working parts would not
  show up here.
